# YC jobs (logged out) and the YC company directory (t_c500164f)

Checked 2026-10-14 with 12 manual `curl` requests to ycombinator.com / workatastartup.com and 2 to Algolia (all >= 3 s apart, default curl UA, no login, no cookies). All URLs below are public pages.

## Answer
- **Jobs**: `https://www.ycombinator.com/jobs/location/remote` and `/jobs/role/{role}/remote` are server-rendered, logged-out, and embed ~20-30 postings as Inertia JSON in a `data-page="..."` attribute (`props.jobPostings[]`). No pagination, no date filter. Each job URL `https://www.ycombinator.com/companies/{slug}/jobs/{id}-{slug}` has a schema.org `JobPosting` JSON-LD with full description, ISO `datePosted`, salary. **Applying always goes through a YC account login** (`applyUrl` = `account.ycombinator.com/authenticate?...`), so the job page is only a lead, not an apply route.
- **Directory**: Algolia app `45BWZJ1SGC`, index `YCCompany_production`. The page `https://www.ycombinator.com/companies` embeds a short-lived (~1 day) secured search key in `window.AlgoliaOpts`. `isHiring:true` = 1493 companies, `regions:"Fully Remote"` + hiring = 194. Fields include `name, slug, website, batch, team_size, all_locations, regions`. **No ATS or jobs-URL field**: ATS must come from `website`.
- **BLOCKER-LEVEL RISK (HUMAN decision)**: the YC Terms of Use (Last Updated September 2026) say users must not "scrape ... or create derivative works based on the Site", and "will not engage in or use any data mining, robots, scraping or similar data gathering or extraction methods". robots.txt does not forbid `/jobs/*`, but the ToS does forbid the practice. See section 6.

## 1. Public pages and robots.txt

robots.txt (https://www.ycombinator.com/robots.txt, 2026-10-14), verbatim for `User-agent: *`:
```
Disallow: /verify/*
Disallow: /library?categories=*&*
Allow: /library?categories=*
Disallow: /library?*
Disallow: /companies?*
Allow: /
```
- `/jobs`, `/jobs/location/remote`, `/jobs/role/...`, `/companies/{slug}`, `/companies/{slug}/jobs/...`, `/sitemap.xml`: **allowed**.
- `/companies?*` (any query string on the directory page) is **disallowed**; the bare `/companies` is allowed. The Algolia host is a different origin and robots.txt does not apply to it.
- https://www.workatastartup.com/robots.txt: `User-Agent: *` / `Disallow:` (nothing disallowed). The WaaS app (`workatastartup.com/jobs`, `/companies`) was NOT fetched; the ycombinator.com copies cover the same data.
- Sitemap https://www.ycombinator.com/sitemap.xml (200, 8 KB) lists only index-style pages (`/jobs`, `/jobs/sitemap`, `/jobs/role`, `/companies/sitemap`, ...), not individual jobs. `/jobs/sitemap` and `/companies/sitemap` were not fetched (UNKNOWN whether they list every job / company). `/jobs/ats` is a marketing page for YC's own ATS product, no data.

## 3. Algolia directory

How the page exposes the key (`https://www.ycombinator.com/companies`, HTML, 2026-10-14):
```
window.AlgoliaOpts = {"app":"45BWZJ1SGC","key":"<long base64 string>","valid_until":1792032710}
```
- `valid_until` 1792032710 = about 2026-10-15 02:50 UTC, i.e. **the key lives ~1 day**. Re-read it from `/companies` at the start of every run; never commit it. (Key not reproduced here on purpose.)
- The key is an Algolia *secured API key* (a base64 of HMAC + query params; the params are readable): `analyticsTags=ycdc`, `restrictIndices=YCCompany_production,YCCompany_By_Launch_Date_production`, `tagFilters=["ycdc_public"]`, `validUntil=1792032710`. So it is deliberately minted for public browser use, scoped to two indices and public records.
- App id `45BWZJ1SGC`, host `https://45BWZJ1SGC-dsn.algolia.net`, index `YCCompany_production` (the other, `YCCompany_By_Launch_Date_production`, is sorted by launch date).

Example request (2 hits, trimmed attributes, hiring + fully remote):
```
POST https://45BWZJ1SGC-dsn.algolia.net/1/indexes/*/queries
x-algolia-application-id: 45BWZJ1SGC
x-algolia-api-key: <value of AlgoliaOpts.key>
content-type: application/json

{"requests":[{"indexName":"YCCompany_production",
 "params":"query=&hitsPerPage=2&page=0&attributesToRetrieve=[\"name\",\"slug\",\"website\",\"batch\",\"team_size\",\"all_locations\",\"regions\",\"status\",\"isHiring\"]&attributesToHighlight=[]&facetFilters=[[\"isHiring:true\"],[\"regions:Fully Remote\"]]"}]}
```
(`params` is URL-encoded in the real call.) Response (trimmed):
```json
{"results":[{"hits":[
 {"name":"Deel","slug":"deel","website":"https://www.deel.com/","all_locations":"San Francisco, CA, USA; Remote","team_size":5000,"isHiring":true,"batch":"Winter 2019","status":"Active","regions":["United States of America","America / Canada","Remote","Fully Remote"],"objectID":"12064"},
 {"name":"Whatnot","slug":"whatnot","website":"https://www.whatnot.com/careers/discover","all_locations":"Los Angeles, CA, USA; Remote","team_size":1500,"isHiring":true,"batch":"Winter 2020","status":"Active","regions":[...],"objectID":"13208"}],
 "nbHits":194,"page":0,"nbPages":97,"hitsPerPage":2}]}
```
Facts from the two Algolia calls:
- `isHiring` is a boolean attribute and facet; `facetFilters=[["isHiring:true"]]` -> **nbHits 1493** (all hiring YC companies on 2026-10-14).
- `regions` facet counts among hiring companies: `Remote` 751, `Partly Remote` 557, `Fully Remote` 194, `United States of America` 1194, `Europe` 135, `India` 51, `Indonesia` 3, `Southeast Asia` 17, `Latin America` 19 (others in the long tail). `regions:Fully Remote` is the strongest remote signal; `Remote` also includes companies whose roles are remote-US only.
- `batch` facet (e.g. `Summer 2024`: 102), `team_size` numeric (filterable via `numericFilters`; UNTESTED).
- Full hit fields seen (default retrieval, 1 hit): `id, name, slug, former_names, small_logo_thumb_url, website, all_locations, long_description, one_liner, team_size, industry, subindustry, launched_at, tags, top_company, isHiring, nonprofit, batch, status, industries, regions, stage, ...`. Use `attributesToRetrieve` to avoid the long description.
- **Pagination cap**: the unfiltered hiring set (1493) exceeds Algolia's default 1000-hit window (a `hitsPerPage=1` query reported `nbPages: 1000` for 1493 hits). UNTESTED beyond that; plan for the 194 `Fully Remote` and 751 `Remote` slices, each < 1000, with `hitsPerPage=100` (or up to 1000), and add facet slices (`batch`) for a full crawl.
- Algolia terms: the key is a client-side search key by design. Algolia's own terms were not read (UNKNOWN). YC's ToS (section 6) still applies to the data.
- No field links to jobs, a careers URL or an ATS. The company page `/companies/{slug}` lists only the company's WaaS jobs (`/companies/deel/jobs/...`, 5 links).

## 4. Mapping a YC company to its ATS

There is no direct field. Proposed chain (not implemented, hit rate UNKNOWN, no sample crawled to avoid hitting 3rd-party sites):
1. `website` from Algolia (sometimes already a careers URL, e.g. Whatnot `https://www.whatnot.com/careers/discover`).
2. If it matches `extractAtsSlug()` in `packages/sources/src/discovery/extract.ts` (greenhouse, lever, ashby, smartrecruiters, workable, recruitee) use it directly.
3. Otherwise fetch the company homepage once and look for links to those ATS hosts (footer "Careers"), or try `/careers` and `/jobs` on the same site; then run `verifyBoard()`.
4. Else search (Brave) `"{name}" careers site:boards.greenhouse.io OR site:jobs.lever.co OR site:jobs.ashbyhq.com` as in `docs/research/t_250e744a-search-api.md` section 4.
Cost: 1-3 requests per company to different hosts, so cache the result in the DB (company slug -> ats/slug or "none") and re-check only every few weeks. Ashby/Greenhouse/Lever dominate YC startups in general, but this share was not measured here.

## 5. Recommended budget and freshness

- Directory refresh: 1 GET `/companies` (key) + 2-5 Algolia queries (`Fully Remote` hiring: 2 pages at `hitsPerPage=100`; `Remote` hiring: 8 pages or 1 page at 1000). Algolia is a CDN-fronted search API; keep to <= 1 query / 3 s per binding rule. Run **weekly** (company/hiring status changes slowly; new batches appear ~4 times a year).
- Job listing: `/jobs/location/remote` + `/jobs/role/software-engineer/remote` (+ a couple of other role slugs the user cares about) = 2-4 requests per run, 3 s apart. The page shows the newest-first window (one job was "1 day" old, others months), so run every **6-12 h**, `minIntervalMinutes: 360`. Detail pages only for postings that survive the cheap filters (title, `location` text) and are not already in the DB: expect single digits per run.
- Page cap: 4 listing pages + <= 10 detail pages per run = <= 15 YC requests, at >= 3 s = ~45 s.
- Freshness: `lastActive` on the job page showed "about 12 hours" for a 1-year-old job, i.e. recruiters touch listings, but `datePosted` is the real age. Listing changes: UNKNOWN (no repeated sampling); assumed daily.

## 6. Terms of use, in plain words

Source: https://www.ycombinator.com/legal/ ("Y Combinator Privacy Policy, Terms of Use, and Trademarks", Last Updated September 2026, read 2026-10-14; the page itself is `noindex`). Verbatim excerpts:
- "you agree not to modify, copy, frame, scrape, rent, lease, loan, sell, distribute or create derivative works based on the Site or the Site Content, in whole or in part"
- "In connection with your use of the Site you will not engage in or use any data mining, robots, scraping or similar data gathering or extraction methods."
- "If you are blocked by Y Combinator from accessing the Site (including by blocking your IP address), you agree not to implement any measures to circumvent such blocking (e.g., by masking your IP address or your User-Agent)."

Plain words: automated reading of ycombinator.com (including `/jobs`, `/companies`) is contractually prohibited, even though robots.txt allows `/jobs/*`. The Algolia directory is the same data via YC's own public key, so it is the same ToS question. Enforcement risk for a personal, low-rate tool is likely low (YC deliberately serves SEO-friendly pages, JSON-LD and a public search key), but that is a judgment, not a permission. Whether the "Site" terms apply to workatastartup.com is unclear (it redirects to YC auth; not read). Lawful reading of these pages by a human in a browser is fine; the tool would be a robot.

AGENTS.md: "Scraping only logged out, at conservative rates, and only for sources listed in PLAN.md" - YC is listed in PLAN.md Tier 2, so the repo rule is met; the ToS conflict is for the owner to weigh. Options for the owner, from least to most risk:
1. Skip the YC page adapter; use only the directory (still ToS-covered) to build the ATS list, then poll the companies' own public ATS boards (employer-published, own terms).
2. Keep YC as a human-in-the-loop link source only (digest shows "browse https://www.ycombinator.com/jobs/location/remote").
3. Implement the adapter as researched (partial listing window, rate caps above), accepting the ToS risk.
If blocked (HTTP 403/429, challenge page) the adapter must stop and report an error, never rotate UA/IP (per ToS and phase-3 conventions "blocks are errors").

## 7. Risks and unknowns
- ToS clause above (high importance).
- Listing pages expose only a window (~20-35 jobs per page); no pagination parameter found. Tried: `/jobs`, `/jobs/location/remote`, `/jobs/role/software-engineer/remote`. NOT tried: `?page=`/query params (the `/jobs` routes are not under the robots `Disallow` list, but behaviour unknown), WaaS JSON (needs login).
- `data-page` structure is YC's internal Inertia props, can change without notice; JSON-LD is the more stable contract.
- Many roles are US-only (`visa: "US citizen/visa only"`, `Remote (US)`): filter by `location` text and `visa`.
- Algolia key rotates ~daily; the `window.AlgoliaOpts` format may change.
- Personal data: `hiringManager` (null in samples) and job descriptions that name recruiters: drop at the Zod layer.
